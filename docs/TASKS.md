## Phase 1 — Ingestion & Extraction (PRD §1, MVP #1) ✅

**Goal:** Upload PDF/PPTX files and persist per-slide/per-page text, tables, and speaker notes with stable indexes.

- [x] Upload UI: multi-file drag-and-drop scoped to an Exam, per-file results and type validation (`src/components/ingest/upload-panel.tsx`)
- [x] Upload API route: writes to `data/uploads/{examId}/`, creates `SourceFile` rows (`src/app/api/exams/[examId]/files/route.ts`)
- [x] PDF extractor (`unpdf`): per-page text, 1-based page index (`src/lib/ingest/pdf.ts`)
- [x] PPTX extractor (custom OOXML via `jszip` + `fast-xml-parser`): slide text, tables, speaker notes (`src/lib/ingest/pptx.ts`)
- [x] Shared `ExtractedUnit` contract for both extractors (`src/lib/ingest/types.ts`)
- [x] Diagram detection per slide → `has_diagram`
- [x] Legibility flags for empty / image-only / low-text units (PRD §3)
- [x] Study-guide parsing into discrete `StudyGuideObjective` rows (`src/lib/ingest/study-guide.ts`)
- [x] Per-file status tracking (`pending` → `extracting` → `ready` / `failed`) with the error message persisted
- [x] Source viewer: browse every unit by index with notes and tables (`/exams/[examId]/sources`)
- [x] Non-destructive re-ingestion: units upserted on `(file, index)`; identical checksum short-circuits entirely
- [x] Tests: 24 passing across extractors, guide parsing, and the re-ingestion guarantee

**Verified:** `typecheck`, `lint`, `build` (zero warnings), and 24 tests pass. Through the live
endpoint: a 12-slide PPTX extracts with notes and a table; an identical re-upload returns
`unchanged`; a 4-page PDF flags its blank page; a `.md` file is rejected; a study guide yields
4 objectives, all rendered in the source viewer.

**Design notes:**
- Slide order comes from `<p:sldIdLst>` in `presentation.xml`, **not** filename sort —
  `slide10.xml` sorts before `slide2.xml`, and a wrong slide number silently corrupts every
  provenance link built on it. A test asserts content and index agree across 12 slides.
- `fast-xml-parser` renders `<a:t>text</a:t>` as a bare string, not a node; the XML walker
  must collect string values or all slide text is silently lost.
- Upload is a Route Handler, not a Server Action: Server Actions cap bodies at ~1MB and
  lecture decks run 20–100MB.
- `ingestSourceFile()` is a standalone function taking a `Db`, so the job queue that
  eventually replaces inline execution can call it unchanged.
- Fixtures are generated by third-party writers (`pptxgenjs`, `pdf-lib`) via `npm run fixtures`,
  not hand-written XML — a fixture shaped to match our own parser would test nothing.

**Known limits (deliberate, deferred):**
- Extraction runs inline in the request; a very large deck holds the connection. Queue is Phase 8.
- PDF tables and diagram labels need the vision pass (post-MVP); PDF `tables` is always empty.
- DOCX and note-image ingestion are rejected at upload with a clear message.

## Phase 2 — Atomic Flashcard Generation (PRD §2, §3, MVP #2)

- [ ] Anthropic client wrapper with strict JSON-schema tool output (ARCHITECTURE principle #2)
- [ ] Chunking strategy: group source units into generation batches within token budget
- [ ] Atomization prompt: discrete sub-questions per concept (origin, trigger, target, action, feedback pattern)
- [ ] Process-card prompt: step, sequence, mechanism, and full-summary card variants
- [ ] Provenance enforcement: reject any card missing `source_slide_id` + verbatim excerpt
- [ ] `CardRubric` generation (essential / optional points, common misconceptions)
- [ ] Deduplication pass across batches preserving distinct nuances
- [ ] Source-vs-AI-supplement badging on `full_explanation`
- [ ] Generation run UI: progress, per-batch errors, resumable
- [ ] Non-destructive regeneration: append/merge proposals, never wipe existing card IDs

## Phase 5 — Adaptive Learn Mode (PRD §5, MVP #5)

- [ ] Round builder: 5–8 concepts per micro-round (user-configurable)
- [ ] Scaffolding ladder: MCQ recognition → immediate typed recall → interleaved re-prompt after 3–5 items → same-session delayed check
- [ ] MCQ distractor generation from sibling deck concepts; randomized placement, length-matched
- [ ] "I guessed" control; post-answer debrief on why a distractor fails
- [ ] Mastery safeguards: typing straight after a reveal does not register mastery
- [ ] Skip-ahead to typed recall for known concepts
- [ ] Persistent-error path: simplified explanation / sub-concept breakdown
